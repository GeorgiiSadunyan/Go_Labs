WebRTC Signaling REST + WebSocket API Protocol
Аутентификация (REST)
POST /api/auth/login {username: string}→ {token: string}
Управление сессией (REST)
POST /api/session {targetUsername: string, type: "video"|"audio"} → {sessionId: string, caller: string, target: string, status: "pending"}
GET /api/session → {sessionId: string, caller: string, target: string, status: string, createdAt: string}
POST /api/session/accept → {sessionId: string, status: "active"}
POST /api/session/decline → {sessionId: string, status: "declined"}
DELETE /api/session → {sessionId: string, status: "cancelled"}
WebRTC сигналинг (WebSocket)
Соединение: Клиент подключается к WebSocket серверу после аутентификации
События от клиента:
signal {type: "offer"|"answer"|"ice-candidate", data: any}
События от сервера:
signal {type: "offer"|"answer"|"ice-candidate", data: any}
session_updated {sessionId: string, status: string, target: string}
Принцип работы:
Клиент аутентифицируется через REST, получает JWT токен
Клиент устанавливает WebSocket соединение с токеном
Все WebRTC сигналы (offer/answer/ice-candidate) передаются через WebSocket
Сервер автоматически маршрутизирует сигналы между участниками сессии
Статус сессии обновляется в реальном времени через WebSocket
Примечание: Все REST endpoints (кроме /api/auth/login) требуют JWT токен в заголовке Authorization: Bearer <token>
